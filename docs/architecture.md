# Архитектура, рендер, общие ловушки

## Архитектура

```
index.html          UI и стили; три canvas'а стопкой (2D-поле, WebGPU-поле, прицел)
serve.mjs           статический сервер без зависимостей
src/
  main.js           связка: контролы, мышь, выбор бэкенда, цикл отрисовки;
                    бэкенд по умолчанию GPU, настройки в localStorage
  core/
    fft.js          radix-2 FFT, столбцы через непрерывный буфер
    grid.js         периодический ящик, таблицы kx/ky/k², маска 2/3
    backend.js      CpuBackend + КОНТРАКТ бэкенда — ВЕСЬ доступ к данным сетки
    webgpuBackend.js  WebGpuBackend: те же ядра на устройстве
    webgpuShaders.js  генераторы WGSL (ядра, FFT, транспонирование, редукции, показ)
    etdrk4.js       ETD-RK4 + φ-функции контурным интегралом (Kassam–Trefethen)
    spectralReal.js общий солвер для KdV-типа (KP-I, KP-II, ZK)
    nlsSolver.js    split-step Фурье (Strang) для НУШ
    waveSolver.js   точный поворот линейной части + Strang-пинок для sine-Gordon
    petviashvili.js поиск профиля солитона + спектральная интерполяция на мелкую сетку
    util.js         вставка профиля с учётом периодики, галилеев буст
  models/           по файлу на семейство, каждая модель = L(k) + нелинейность + пресеты
  render/
    colormaps.js    256-цветные рампы, все тёмные в нуле
    renderer.js     CPU-рендер в ImageData + AimOverlay (прицел, поверх обоих)
    gpuRenderer.js  фрагментный шейдер по тому же буферу поля
tools/
  verify.mjs        распространение лампа, скорость, инварианты
  residual.mjs      невязка PDE на аналитическом лампе — определяет знак σ
  gpu-check.mjs     GPU против CPU: FFT, все 7 моделей, редукции
  gpu-profile.mjs   ГБ/с по каждому ядру, медиана раундов со спредом
  gpu-stability.mjs дрейф инварианта до равного физического времени, CPU и GPU
  inflight.mjs      глубина очереди против пропускной способности, все сетки
  bench.mjs         мс/шаг для CPU и GPU на всех сетках, со скриншотами
  smoke-browser.mjs прогон всех моделей в реальном браузере + скриншоты
  shoot.mjs         точечный скриншот: модель, пресет, сетка, бэкенд, моменты t
```

Браузерные инструменты используют `playwright-core` и **уже установленный
Edge** (`channel: 'msedge'`) — браузеры не качаются, это единственная
зависимость проекта. Все они **headless и без флагов запуска**: окно можно
случайно задеть мышью и испортить замер, а флаги — испортить адаптер.

```bash
npm start                                        # сервер на 8123
npm run gpu-check                                # GPU против CPU: FFT, модели, редукции
npm run gpu-profile 1024 5                       # ГБ/с по ядрам: сетка, раундов
npm run gpu-stability                            # дрейф инварианта до равного t
node tools/inflight.mjs                          # глубина очереди против шагов/с
npm run bench                                    # мс/шаг, CPU и GPU, все сетки
node tools/smoke-browser.mjs shots               # все модели, CPU
node tools/smoke-browser.mjs shots gpu 512       # то же на GPU, сетка 512²
node tools/shoot.mjs shots kpI 1 256 5,10,20 gpu # модель, пресет, сетка, моменты, бэкенд
```

**Интерфейс модели:** `{ id, name, blurb, family, field, grid, dt, params,
spawnKinds, presets, create(backend, grid, dt, params) }`. `create` возвращает
`{ step, clear, field, target, peak, spawn(x,y,drag,kind), applyPreset,
diagnostics, time }`. `drag` нормирован в [-1,1] (четверть окна = максимум).

**Публикация: приложение статическое, и это надо не сломать.** Оно выложено
на GitHub Pages без сборки — публикуется корень репозитория как есть.
Держится это на четырёх свойствах, каждое из которых легко потерять:

- **Сетевых запросов нет вообще** — ни `fetch`, ни воркеров, ни внешних CDN.
  WGSL зашит строками в `webgpuShaders.js`; вынести его в отдельные `.wgsl`,
  подгружаемые `fetch`, — значит завести MIME-типы и CORS на ровном месте.
- **Все пути относительные.** `index.html` грузит `./src/main.js`, дальше
  относительные импорты. Абсолютный `/src/...` работает локально и молча
  ломается на Pages, потому что там сайт живёт на подпути `/soliton/`.
  Именно так и написаны `gpu-check.mjs` и `gpu-profile.mjs` — им можно,
  они ходят к `serve.mjs`, а не на Pages.
- **WebGPU требует secure context.** У Pages есть https, у `localhost` —
  исключение; всё остальное (например, http на IP в локальной сети) отдаст
  `navigator.gpu === undefined` и тихо уронит на CPU-бэкенд.
- **`serve.mjs` — не бэкенд**, а `readFile` → `res.end`, нужный только
  потому, что ES-модули не грузятся с `file://`. Логики в нём быть не должно:
  всё, что он начнёт вычислять, на Pages не поедет.

`.nojekyll` в корне — чтобы Jekyll не съел каталоги с `_` в начале имени,
если такие появятся. Кеширование на Pages агрессивное: после пуша обновление
видно не сразу, в отличие от `Cache-Control: no-store` из `serve.mjs`.

`field()` — хостовый `Float64Array` (на GPU это скачивание, отстаёт на кадр).
`target()` — объект поля бэкенда, в `.re` лежит то, что рисуем: им кормится
GPU-рендер, и поле при этом вообще не покидает устройство. `peak()` — max|поле|
для сторожа расходимости; отдельный метод, потому что на 1024² лишний проход по
миллиону ячеек стоит заметных миллисекунд.

## Рендер

Поле рисуется в `ImageData` в разрешении сетки и растягивается билинейным
масштабированием браузера — дёшево и мягче, чем nearest neighbour на 128².

**Цвет = карта значения × ламбертова подсветка по градиенту.** Нормаль берётся из
конечных разностей поля, свет падает сбоку. Без этого горб — просто цветное пятно;
с этим он читается как горб на поверхности, что и было целью.

**Все три карты тёмные в нуле, и это не вкусовщина.** Невозмущённое поле занимает
почти весь кадр: со светлой серединой (классическая расходящаяся карта сине-бело-красная)
картинка забеливалась, а структуры тонули. Это был реальный дефект, пойманный на
скриншотах. Сейчас:

- `height` (KP, ZK) — расходящаяся вокруг нуля: провал голубой, ноль почти чёрный,
  гребень тёплый и яркий;
- `intensity` (НУШ) — последовательная от чёрного, ноль = «ничего»;
- `phase` (sine-Gordon) — циклическая, **тёмная при u = 0, ±2π**, потому что это один и
  тот же вакуум. Светится ровно стенка кинка, то есть то единственное, что несёт энергию.

Автомасштаб сглажен (коэффициент 0.06), иначе кадр мигает на каждом всплеске при
столкновении.

В GPU-режиме всё это же считает фрагментный шейдер прямо по буферу поля —
почему так и чем отличается картинка, см. «Рендер: почему у GPU свой путь».
Правило про тёмный ноль и формулы освещения там продублированы буквально:
меняешь одно — меняй и второе.

## Ловушки

- **FFT только для степеней двойки.** `Grid` не проверяет — `fft.js` бросает. Поэтому
  выбор сетки в UI только 128 / 256, промежуточных нет.
- **Пресет без координат даёт тихий ноль.** Так и было с X-взаимодействием KP-II:
  линейный солитон тянется через весь ящик, координат у него нет, `s.x` был `undefined`,
  `Math.round(NaN)` дал `NaN`-индексы и запись ушла в никуда — поле осталось пустым, без
  единой ошибки. Теперь `addCentered` бросает исключение на не-конечном центре, а пресеты
  подставляют центр по умолчанию. **Не убирай эту проверку.**
- **Инварианты — первое, что поедет** при слишком большом шаге. Для KP смотри L2-норму:
  масса `∫∫u` там бесполезна (см. выше). Для НУШ мощность плоха как признак беды с
  другой стороны: split-step сохраняет её точно даже когда всё уже развалилось —
  смотри гамильтониан. **На GPU она вдобавок медленно течёт вниз** (f32, около
  −0.5% за 10 тыс. шагов), так что убыль мощности там не значит ничего; см.
  «Дрейф мощности НУШ на GPU».
- **Сохранённая L2-норма ≠ решение правильное.** Линейная часть сохраняет её точно при
  любом шаге. Пик и форма ломаются раньше нормы.
- **Спавн может вернуть `false`** — `solveProfile` не сошёлся (кубично-квинтичное при
  μ ≳ 1). Это не сбой, там просто нет солитона; UI показывает сообщение.
- **Браузерные инструменты требуют установленного Edge** (`channel: 'msedge'`).
  Браузер не качается — это сознательно, единственная зависимость проекта
  `playwright-core`.
- **ES-модули не работают с `file://`** — только через `npm start`.
- **Приложение помнит настройки, и это ломает инструменты.** Модель, сетка,
  бэкенд, темп и рельеф лежат в `localStorage`, а бэкенд по умолчанию теперь
  GPU. Инструмент, который просто открывает страницу, померит прошлую сессию.
  Каждый инструмент из `tools/`, водящий приложение, обязан чистить хранилище
  **через `page.addInitScript` (то есть до скриптов страницы, не после)** и
  задавать бэкенд явно в обе стороны — иначе `smoke-browser.mjs shots` тихо
  прогоняет GPU вместо CPU, что уже случалось.
