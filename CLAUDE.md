# soliton — интерактивные 2D-симуляции солитонов

Браузерное приложение: несколько 2D нелинейных волновых уравнений, локализованные
солитоны порождаются мышью, видно как они летят и сталкиваются. Псевдоспектральные
солверы, два взаимозаменяемых бэкенда — CPU (JS, float64) и GPU (WebGPU, float32),
сетки от 128² до 1024².

Запуск: `npm start` → http://localhost:8123 (ES-модули требуют http, с `file://`
не работает). По умолчанию поднимается GPU; настройки живут в `localStorage`.

---

## Правило ноль: держи документацию актуальной

**Обновляй документацию по ходу работы, а не в конце.** Значимый шаг — это всё,
после чего документ становится неверным или неполным: новый модуль, изменённый
контракт, подобранная константа, установленный численный факт, пойманная
ловушка, **отвергнутая гипотеза**. Записывай **замеренные числа**, а не
«сделано»: «пик 2.55 → 2.46 при точном 2.56» переживает сессию, «лампа
работает» — нет. Отрицательный результат с числом ценнее молчания: он избавляет
следующего от той же работы.

**Куда писать.** В тот файл `docs/*.md`, чей это предмет (таблица ниже) —
**не сюда**. Этот файл грузится в контекст целиком каждую сессию, поэтому в нём
только маршрутизация; каждая строка здесь оплачивается на каждой задаче, даже
не связанной с ней. Трогай его, только если появился или исчез документ, либо
изменилось правило из этого раздела.

**История** — отдельной записью с датой в начало `docs/history.md`. Не
переписывай прошлые записи: то, что оказалось неверным, ценно вместе с тем,
как это выяснилось.

**Если документ противоречит коду — прав код, а документ содержит баг.**

Названия разделов уникальны на весь проект, так что ссылка вида «см. «Ловушки

## Что укусит раньше, чем ты откроешь документ

Пять вещей, которые ломаются **молча** — без исключения, без ошибки в консоли,
с правдоподобным результатом. Подробности по ссылкам.

1. **Выше `core/backend.js` никто не индексирует буферы поля.** Весь доступ —
   через именованные ядра контракта. Это и есть то, что делает бэкенды
   взаимозаменяемыми. → «GPU-бэкенд»
2. **Спектр на GPU лежит транспонированным.** Всякая вещественная таблица,
   попадающая в ядро, спектральная и обязана транспонироваться; физика в обе
   стороны — нет. Ошибка здесь даёт совпадающий forward и развалившийся
   round-trip. → «Транспонированный спектр»
3. **Вещественные таблицы кешируются по идентичности объекта.** Мутировал
   `grid.mask` на месте — GPU продолжит считать по старой копии. Меняешь
   таблицу — делай новый массив. → «Ловушки GPU»
4. **Один замер — это не замер.** Разброс на неизменном ядре здесь доходит до
   2.5×. Сравнивай с `copy` из того же прогона; разницу меньше спреда считай
   нулём, а число выше потолка `copy` — сломанным замером, а не находкой.
   → «Ловушки GPU», «Что померено и отвергнуто»
5. **Пустое поле — законный ответ.** `spawn` и `applyPreset` возвращают `false`,
   когда солитона при этих параметрах не существует. Не «чини» это молчанием.
   → «Ловушки»

## Команды

```bash
npm start                                        # сервер на 8123
node tools/residual.mjs                          # невязка PDE — определяет знак σ
node tools/verify.mjs                            # распространение лампа, инварианты
npm run gpu-check                                # GPU против CPU: FFT, модели, редукции
npm run gpu-profile 1024 5                       # ГБ/с по ядрам: сетка, раундов
npm run gpu-stability                            # дрейф инварианта до равного t
node tools/inflight.mjs                          # глубина очереди против шагов/с
npm run bench                                    # мс/шаг, CPU и GPU, все сетки
node tools/smoke-browser.mjs shots               # все модели в браузере, CPU
node tools/smoke-browser.mjs shots gpu 512       # то же на GPU, сетка 512²
node tools/shoot.mjs shots kpI 1 256 5,10,20 gpu # модель, пресет, сетка, моменты, бэкенд
node tools/mobile-shots.mjs shots               # раскладка и жесты на телефонных вьюпортах
```

Полная проверка снизу вверх: `residual` → `verify` → `smoke-browser shots` →
`gpu-check` → `smoke-browser shots gpu 512`. Ожидаемые числа — в «Опорные числа».

Все браузерные инструменты используют `playwright-core` и **уже установленный
Edge**, работают **headless и без флагов запуска**, и чистят `localStorage` до
загрузки страницы. Флаги портят адаптер, окно можно задеть мышью, а
непочищенное хранилище заставит инструмент мерить прошлую сессию.

## Симптом → документ

| что видишь | куда |
|---|---|
| решение разошлось, инварианты поехали | «Если что-то ломается» |
| лампа рассыпается на KP-I | «Численные факты» (знак σ) |
| пусто после пресета, картинка забелена | «Ловушки» |
| GPU считает не то | «Ловушки GPU», затем `npm run gpu-check` |
| GPU медленнее, чем ожидалось | «Производительность: где уходит время» |
| мало шагов в секунду, но ядра в порядке | «Дозировка кадра» |
| рябь по всему полю в НУШ | «Рябь в НУШ» (это излучение, а не дефект) |
| на телефоне поле под шторкой, жест не ловится | «Мобильная раскладка» |
| мощность НУШ убывает на GPU | «Дрейф мощности НУШ на GPU» (f32, известно) |

## Состав

```
index.html   UI, три canvas'а стопкой       serve.mjs   статический сервер
src/main.js  связка, цикл кадра, настройки  src/core/   FFT, сетка, бэкенды, солверы
src/models/  по файлу на семейство          src/render/ цветовые карты, два рендера
tools/       проверка и замеры              docs/       документация (таблица выше)
```

Модели: `kpI` (главная), `kpII`, `zk` — KdV-типа через один солвер;
`nlsCubic`, `nlsCQ`, `nlsSat` — split-step; `sg` — волновой солвер.
Три из них стоят как контрпримеры, а не как рабочие модели — почему именно
такой набор, см. «Почему именно эти семь».
